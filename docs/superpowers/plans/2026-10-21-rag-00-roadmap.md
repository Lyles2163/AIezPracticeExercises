# 教材考点知识库 RAG 实现计划（0–7 分段总览）

> **For agentic workers:** 本总览是入口。每个阶段有一份独立计划文件，执行某阶段时只读该阶段的计划，并按其中的 checkbox 逐项推进。计划使用 `- [ ]` 语法跟踪进度。

**Goal:** 按 `2026-10-12-elasticsearch-rag-design.md` 的 8 个阶段，在 `AIModule` 落地知识库文档 RAG、题目语义搜索、上传自动录题三条流水线，共用一套混合检索内核。

**Architecture:** MySQL 是真相源，Elasticsearch 只承担检索派生视图；写路径异步执行，`rag.async=poll` 为默认派发方式，RabbitMQ 是可选派发层；入库状态机、断点续跑、心跳回收全部落在 MySQL。读路径统一走 `RetrievalService`：BM25 + kNN → RRF 融合 → 两腿逐字重复的权限过滤。

**Tech Stack:** Java 21 / Spring Boot 3.2.4 / Spring AI 1.0.0-M7（OpenAI starter 调百炼 embedding + DeepSeek chat）/ elasticsearch-java 9.5.4 / Tika 3.2.3 + PDFBox 3.0.5 / jtokkit 1.1.0 / MyBatis-Plus 3.5.17 / Spring AMQP + RabbitMQ 4.3.6 / MySQL 8 / JUnit 5 + Mockito。

**Spec:** `docs/superpowers/specs/2026-10-12-elasticsearch-rag-design.md`

## 3. 已核实并必须遵守的 spec 修正

以下结论来自 2026-10-21 对本机与依赖 jar 的实测，执行时以本节为准（spec 原文相应段落作废）：

1. **Tika 3.2.3 不存在 `org.apache.tika.sax.PaginationHandler`。** 已下载 `tika-core` 与全部 `tika-parser-*-module` 并逐个检索，没有任何 `PaginationHandler` 类。PDF 逐页文本改用 **PDFBox 3.0.5** 的 `PDFTextStripper`（`setStartPage/setEndPage` 逐页抽取）；DOCX/HTML/TXT 由 Tika 抽成连续文本，TXT 按 `\f` 分页，其余格式 `pageNo=1`。`DocParser` 接口不变，将来可换多模态实现。
2. **`qb_question.owner_id=1` 表示公共题库，不是 spec 假设的 `NULL/0`。** 依据 `PracticeModule/.../QbQuestion.java:31` 的列注释。`QuestionIndexService` 的 scope 判定为：`owner_id = 1` → `official` + `owner_name=''`；`owner_id <> 1` → `personal` + JOIN `users_dev.username`。`subject_id` 为 NULL 时写 `0`。回灌前仍执行 spec 9.1 的分布查询做数据核实（需用户同意）。
3. **用户表名是 `users_dev`，用户名列是 `username`**（`UserModule/.../Users.java:15,27-28`），不是 spec 写的 `users`/`user_name`。题目回灌 JOIN 用 `users_dev u ON u.id = q.owner_id`。
4. **对话子系统当前完全不存在**：全仓 grep 不到 `SseEmitter`、`ai_conversation`、`ai_message`、`thought_step`。阶段 6 先实现“对话最小闭环”（4 张表 + stream + 历史消息），再接入 RAG；不实现 effort 之外的模型选择、断点续传等非 RAG 内容。
5. **ES 当前未启动且没有 IK 插件**：安装目录 `F:\ES\elasticsearch-9.5.4`，TLS + 认证开启，`http_ca.crt` 在 `config/certs/`；密码在 `F:\ES\密码.txt`（不得复制进仓库）。用户已确认安装 IK。
6. **ES 客户端版本**：`elasticsearch-java:9.5.4` 的传输层是 `elasticsearch-rest5-client`，Boot 3.2.4 的 `RestClient` 自动配置不可用；必须手写 `Rest5Client` + `Rest5ClientTransport` + `JacksonJsonpMapper`。`RRFRetriever.retrievers` 接收 `List<RRFRetrieverEntry>`，每条 entry 再包一个 `Retriever`。
7. **管理员判定没有现成通道**：网关注入的只有 `X-User-Name`，没有角色。阶段 0 增加 `rag.admin-names`（逗号分隔用户名）作为临时管理员名单；名单为空时所有管理员接口与 `official` 上传一律拒绝。将来网关注入角色后再替换。
8. **百炼 embedding 配置**：Spring AI M7 支持 `spring.ai.openai.embedding.base-url` / `api-key` / `options.dimensions`，已用 `javap` 核实。单次最多 20 条，`EmbeddingGateway` 取 `batchSize=10` 留余量。
9. **`spring-ai-rag` 缓存的版本是 1.1.2，不是 1.0.0-M7**。spec 1.4 的 advisor 实验只作为阶段 6 的一次性可选项，不进入主路径；需要时单独下载 `spring-ai-rag:1.0.0-M7`，若与 M7 BOM 冲突则直接放弃该实验（不影响任何验收项）。
